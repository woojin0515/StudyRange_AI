# StudyRange AI UI/UX Guidelines

## 목적

- 학습 작업 완료 속도를 높이는 정보 구조를 유지한다.
- 데스크톱/태블릿/모바일에서 동일한 태스크 흐름을 제공한다.
- 화면 간 시각 규칙을 통일해 운영형 제품 경험을 만든다.

## 핵심 원칙

1. 한 화면 한 목적: 페이지의 핵심 CTA는 1개를 우선 강조한다.
2. 상태 가시성: 로딩/빈 상태/오류를 항상 명시한다.
3. 인지 부하 최소화: 옵션을 줄이고 기본값으로 시작한다.
4. 접근성 우선: 키보드 포커스, 대비, 명확한 라벨을 기본으로 한다.

## 디자인 토큰

- 전역 토큰은 `src/StudyRange.Web/wwwroot/app.css`의 `:root`를 기준으로 사용한다.
- 대표 토큰:
  - 배경/표면: `--sr-bg`, `--sr-surface`
  - 텍스트: `--sr-text`, `--sr-muted`
  - 강조색: `--sr-primary`, `--sr-primary-hover`
  - 경계/포커스: `--sr-border`, `--sr-focus`

## 레이아웃 규칙

- 공통 폭 클래스:
  - `sr-shell` (기본 1280)
  - `sr-shell-lg` (1200)
  - `sr-shell-md` (960)
  - `sr-shell-sm` (760)
  - `sr-shell-xs` (520)
- 페이지 루트 컨테이너는 위 클래스 조합으로 최대폭을 맞춘다.

## 컴포넌트 규칙

- `MudPaper` Outlined를 기본 카드로 사용하고 과도한 그림자는 금지한다.
- 버튼은 문장형 텍스트를 유지하고(전역 `text-transform: none`) 페이지당 1개 핵심 CTA를 강조한다.
- 표는 작은 화면 대응을 위해 `MudTable Breakpoint="Breakpoint.Sm"`를 기본 적용한다.

## 반응형 규칙

- 기준 폭:
  - 모바일: `<= 600px`
  - 태블릿/중간: `<= 960px`
- 모바일에서는 Stack을 세로 전환하고 주요 버튼을 가로폭 100%로 확장한다.

## 구현 체크리스트

1. 새 페이지에 `sr-shell*` 적용
2. 로딩/빈 상태/오류 문구 제공
3. 표가 있으면 `Breakpoint` 지정
4. 모바일에서 CTA 터치 영역(버튼 폭/간격) 확인
